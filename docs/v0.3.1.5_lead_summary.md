## 2. 8 个问题回答（Lead）

**Q1：Evidence Schema 是否还存在 published_at → available_at 自动迁移？**
**NO。** normalize 迁移分支已删除（I1 源码断言）。

**Q2：只有 published_at、没有 proven available_at，是否可能进入交易决策？**
**NO。** 即使 published<cutoff 也不能 eligible（I2/I3 回归测试）。

**Q3：Time Gate 是否只读取 available_at？**
**YES。** `time_eligible` 只判 available_at（+ init Strong Impossibility），published_at 完全不参与（I6）。

**Q4：若 Source 确实证明 published_at == available_at，是否由 Source Adapter 显式生成，而非 Schema 自动推断？**
**YES。** Adapter 显式写 `available_at=published_at` + `SOURCE_PUBLISHED_AT_IS_PROVEN_AVAILABILITY`，Schema 保留（I5）。

**Q5：旧测试中"只有 published_at 也 eligible"的逻辑是否已删除？**
**YES。** 全部更新为 available-at-only 语义（显式 available_at 或断言 NOT ELIGIBLE）。

**Q6：Golden Case E 是否仍然 init>cutoff、available UNKNOWN、NOT ELIGIBLE、final NO_TRADE？**
**YES。** I11-I13 + clean clone 模拟验证。

**Q7：manifest 是否不再错误描述 Case E 为 available_at > cutoff？**
**YES。** 已改为 initialization_time>cutoff / available_at not proven（I14）。

**Q8：本轮是否修改任何交易核心？**
**NO。** 模型、Alpha、Risk Gate、Rule Engine、PnL、Golden Case outcome 全部未动（H15/I11-I13）。

## 4. 诚实边界

- Case E 的 published_at 为保守发布上界估算，页面明确标注 `Published At Estimate`，不冒充真实发布时刻；`Available At: UNKNOWN / NOT PROVEN` 是核心诚实表达。
- `gfs_forecast._finalize_eligible` 保留为一致性防御（available-at-only 下 AsOfRecord 与 Schema 重算天然一致，不触发清空 published）。
- clean clone 模拟：LF checkout 下 5 个 artifact 文件 canonical hash 全 PASS；Case E 稳定展示 `available_at=''` + `INITIALIZATION_AFTER_CUTOFF` + final 不变。

## 5. 结论

**Final Invariant 成立：**
- `published_at` 只是 metadata
- `available_at` 是唯一 eligibility timestamp
- 没有 available_at → 不使用
- init 已晚于 cutoff → 直接证明不可用
- Source 能证明 publication == availability → Adapter 显式写 available_at
- 下游绝不猜
