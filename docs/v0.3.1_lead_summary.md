## 3. Lead 回答 7 个问题

**Q1：仓库现在是否存在真正的 LLM API 调用？**
**YES。** `code/llm_copilot.py` 的 `OpenAICompatClient` / `AnthropicClient` 通过 httpx/requests 直连（`tools` 参数原生 function calling），或经受控 JSON Tool Router。**无 `LLM_API_KEY` 时降级**（`LLM NOT CONFIGURED`，Tool 仍确定性执行），核心流程不受影响。

**Q2：LLM 是否参与 BUY/SELL/NO_TRADE 的生成？**
**NO。** 方向恒来自 `decision_service`（Model+RiskGate+RuleEngine）；System Prompt + 程序化数字守卫双重约束（LLM 声称值与 Tool 结果偏差>5% 即拦截）。

**Q3：LLM 到底解决了什么业务问题？**
把结构化决策结果（模型/证据/风险门/规则/历史案例/数据溯源）组织成交易员可理解的自然语言，并支持"为什么不卖/数据从哪来/后来赚了吗"等连续追问；它只解释，不决定方向、不编造数字。

**Q4：Web 页面是否真正调用 V0.3.1 白盒 Pipeline？**
**YES。** `mvp_web.py` 决策对象 100% 来自 `DecisionService`（7 Section 全部真实结构化，`actual_*` 仅 Lock 后 Reveal 出现）。

**Q5：用户可否问"为什么这笔不交易"且 Agent 通过 Tool Calling 获取真实结果回答？**
**YES。** 预设路由 + `get_decision` tool 获取真实 final_recommendation/reason_codes，Trace 展示 Tool 调用链。

**Q6：页面能否清楚展示数据来源/可获得/eligible/模型判断/RiskGate/最终/盈亏？**
**YES。** S2（Data&Provenance，含 availability_basis）、S3（Model + 特征贡献）、S4（Evidence 含被拒原因）、S6（RiskGate reason 业务翻译）、S7（白盒推导）、Reveal（实际 DA/RTPD/PnL）+ Audit。

**Q7：当前是否已证明稳定盈利？**
**NO。** 明确标注 `MODEL SIGNAL IS EXPERIMENTAL / CURRENT ALPHA = WEAK / MVP ≠ 已验证盈利系统`。

## 4. 现场演示闭环（成功标准）

选择黄金案例 → RUN → 展示 10:00 前数据/模型/特征/证据/相似案例/RiskGate/RuleEngine → BUY/SELL/NO_TRADE → Ask Agent（"为什么不卖？"经 Tool Calling 真实回答 + Trace）→ LOCK → REVEAL（实际 DA/RTPD/PnL）→ 再问"为什么这次错了？"（Post-trade tool）→ 复盘。

全程：LLM 不决定方向、数字来自 Tool、证据有时间戳、无穿越、MOCK 不参与、可解释、可追溯、可复盘。

## 5. 诚实边界

- 交易核心冻结（未改模型/规则/阈值/PnL）；Web/CLI/Agent 三端同源（GFS 统一、available_at 统一）。
