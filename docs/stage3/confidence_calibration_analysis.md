## 4. 结论：CONFIDENCE NOT CALIBRATED

**置信度在本数据上既不是方向概率，也不是盈亏概率，更不是风险度量。** 证据：
1. **accuracy 随 conf 无单调性**：全区间 ~60–68% 持平，>0.80 桶最低（60.3%）。用 confidence 筛方向不会提升正确率。
2. **ML 模型的 confidence 与 PnL 反相关**：高置信桶亏得更狠（Interpretable >0.80：−75.2/笔；CatBoost 0.70–0.80：−105.3/笔）——模型在 CONTROLX 稀缺定价日前对「BUY」最自信，恰是灾难。这是**过度自信（overconfidence）+ 置信与尾部风险同源**：越接近极端事件，模型越确信逆漂移方向。
3. 三模型 confidence 定义不同（一致性 / |2p−1| / 混合式），**无法跨模型统一校准**。

**需要哪种 calibration？**
- **Platt / Isotonic（把 confidence 重标成 P(方向正确)）对本问题无效**：因为 accuracy 在各桶基本恒定，任何单调校准都会被拉平成 ~0.63 的常数，不产生可分性。若必须做，Isotonic 是更合适的（非参数、可捕捉非单调），但预期结果是一条平坦曲线，反而正式证实「置信度无方向信息」。
- **真正缺的是尾部/量级校准，而非概率校准**：亏损由 CONTROLX 右尾（BUY）与 ELCA 左尾（SELL）的稀疏极端事件驱动。需要的不是 P(return>0)，而是：
  - **分位/量级校准**：对 expected_return 做 quantile（如 LightGBM quantile 0.1/0.9）或 EVT（广义帕累托拟合尾部），给出尾部风险区间，替代「单点置信」；
  - **方差/波动校准**：用 spread_std7/14 等（已在 canonical）做风险门（注意：阶段二敏感性显示波动过滤会把 Rule 的 +79k 打到 +2k，说明这类过滤在保护尾部的同时也掐掉了主要利润源——需接受低收益换低尾部）；
  - **节点-方向校准**：先按 node 漂移符号对齐方向（CONTROLX→SELL / ELCA→BUY），再谈置信。
- **建议实践**：不要用现有 confidence 做交易决策过滤；把「高置信 BUY on CONTROLX」显式视为危险信号（应触发 NO_TRADE 或反向下单的候选），而不是买入理由。

**标记：CONFIDENCE NOT CALIBRATED。**
