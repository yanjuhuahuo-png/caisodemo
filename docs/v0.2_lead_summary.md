## 2. 架构变化（V0.1 → V0.2）

- **删掉**：Model Committee 作为线上架构（"双 ML 同向=相关误差放大"的结构缺陷）。
- **改定位**：Rule = benchmark；Interpretable = dev/验证工具；CatBoost/LightGBM = 单一 Production Predictive Model（只出预测量，不出 BUY/SELL）。
- **新增 8 步流水线**：Predictive Model → Agent Evidence Collection → **Evidence Time Gate** → Case Retrieval → Risk Gate → White-box Rule Engine → Human Confirmation → Post-trade Review。
- **硬约束**：Evidence 必须 `published_at ≤ decision_cutoff`（10:00）才能进决策；`decision_eligible` 程序计算、LLM 禁止判断；post-decision 只进复盘。

## 4. V0.2 相比 V0.1 的真实业务价值（最终回答）

> **不是"模型更准"。V0.2 的价值在风险护栏、可解释、可审计、防穿越——不在 PnL。**

| 问题 | V0.2 是否做到 | 证据 |
|---|---|---|
| 减少无意义交易 | ✅ | Risk Gate 移除 test −149,603 系统负期望交易；coverage 41%→5.8%（高选择性） |
| 减少极端亏损 | ✅ | maxDD −138k→−3k、worst −2,216→−208、CVaR −1,097→−198（但 V0.1 gate 已部分做到） |

## 5. 诚实结论与局限

1. **V0.2 不提升 PnL**：Model+Gate −820（vs V0.1 +962），都输给漂移基准；盈利价值仍缺失（信号弱、CONTROLX SELL 在 v2 上负 EV）。
2. **gate 是护栏不是引擎**：它能拦掉 −149k 灾难，但保留集仍负（模型侧问题）；R6 低样本误伤 ELCA BUY（+731 正 EV 被关）。
3. **coverage 极低（5.8%）**：几乎只做安全节点/方向，代价是交易机会大幅缩减。
4. **仍缺**：真实 as-of weather forecast、本地燃气价、可再生能源出力、概率/尾部校准、Agent 信息检索接入（当前 evidence 全 UNCERTAIN）。

## 6. 下一步（数据优先）

1. 补 `[当前缺失真实 as-of weather forecast archive]`（可再生能源出力 / 负荷修正 / 停机阻塞）。

### 8.1 PnL 逐笔对账（两套候选口径，不混写）

强制校验 `Original PnL == Accepted PnL + Rejected PnL`（逐笔 level，不成立自动报错）：

| 口径 | Dataset | Original | Accepted | Rejected | Trade Count | Coverage |
|---|---|---|---|---|---|---|
| **Production Signal Set** | test（3 节点，阈值候选） | −119,541 | −820 | −118,721 | 181 | 13.2% |
| **Calibration Candidate Set** | val+test 全行（对齐 calibrate.py） | −186,178 | −662 | −185,516 | 197 | 1.7% |
| **Calibration Candidate Set** | val+test 阈值候选 | −156,084 | −662 | −155,422 | 197 | 4.0% |
| **Calibration Candidate Set** | val 单独阈值候选 | −36,543 | +158 | −36,701 | 16 | 0.5% |

- `Production Signal Set` = Predictive Model only 在 test 的完整候选（\|er\|≥5 & conf≥0.2）；`Calibration Candidate Set` = Risk Gate 校准/验证时用的全候选（主口径 = val+test 全行，对齐 `calibrate.py::gate_impact`）。
- 四行均满足恒等式；Calibration 主口径的 Accepted 与 Production 一致（197 = 181 test + 16 val，弱信号行全部被 Rule Engine 拦为 NO_TRADE）；Rejected PnL 大幅为负 → gate 的 REJECT 有正价值（避免亏损）。

### 8.2 Agent Evidence A/B（第一次真正的 A/B）

- **A：No Evidence**（Model → Risk Gate → Rule Engine）；**B：With Evidence**（Model → 极端状态证据 → Evidence Time Gate → Risk Gate[R12] → Rule Engine）。其余全部不变。
- **证据（诚实声明）**：联网不可用、无 GFS 缓存 → 用 Agent D 的 as-of 判定逻辑 + 现有特征近似：目标日 T 取决策时点前 [T-8,T-2] zone 天气日均值相对历史同月（train+val）z-score，|z|≥2.0 → 极端状态 → 证据 severity≥WARNING，`directional_effect=UNCERTAIN`（不判方向），时间字段复用 D 的 GFS 口径，`decision_eligible` 全 True。
- **ZP26 test 结果**：A −820（181 笔）→ B +1,113（87 笔），净 +1,933；避免尾部亏损 5,162 / 误伤盈利 3,229；maxDD −3,046→−1,099、Sharpe −0.67→+0.99。
- **ELCA**：A/B 无差异（R7b+R6 已全关，0 交易）。

### 8.3 判定：**YES_WITH_LIMITS**（不是 YES）

- 本窗口证据 REJECT 确实减少亏损并改善风险调整收益；但**误伤严重**（单笔最赚 +2,251 被误伤）、改进集中在少数极端日、**阈值未能在 val 校准**（val 仅 16 笔 gate-accepted 交易，无极端高温样本）、证据为**离线持久性代理**而非真实 GFS 预报、2026-06-23/06-30 崩塌日天气 z 分位低证据抓不到。
- 结论：Agent Evidence 有潜力但**未证伪误伤代价**；接入真实 as-of 数据源（在线 GFS）并做 val 校准后再下「有价值」的最终判定。
