## 2. 8 个问题回答（Lead）

**Q1：clean clone（跨平台 checkout）的 manifest 哈希是否 PASS？**
**YES。** 新增 canonical 哈希：文本文件（manifest/metadata/cases/predictions）统一 **CRLF→LF 归一化后再 SHA-256**，配合 `.gitattributes text eol=lf`。验证：CRLF 与 LF 两个版本 canonical 哈希一致（F1）；模拟 clean clone 强制 LF 后 4 个输出文件哈希全部匹配 manifest（PASS）。二进制（parquet）原样哈希不受影响。

**Q2：测试计数是否唯一、不重复、不硬编码？**
**YES。** `run_tests.py` 对全仓库 `test_*.py` 做**一次** discovery 并运行一遍，`TOTAL = result.testsRun`（动态推导），`PASSED = TOTAL − FAILED − SKIPPED`。当前实跑 **TOTAL 300 ｜ PASSED 300 ｜ FAILED 0 ｜ SKIPPED 0**（285 旧 + 15 新 v0312）。源码无 `n_total = 300/285` 之类写死（F2/F15 守护）。

**Q3：Web / CLI / LLM Tools 是否共用同一个 DecisionService / DecisionSnapshot？**
**YES。** `mvp_demo.py` 重构后不再自己算任何决策字段，直接调用 `DecisionService.run_decision(dd, node, hour)` 拿同一个 DecisionSnapshot，并走同一套 `lock_decision → reveal_decision` 生命周期（Outcome Access Control）。F5/H13 验证 Web 与 CLI/Tool 的 final 与数值一致。

**Q4：仓库内是否存在第二套 RiskGate / RuleEngine？**
**NO。** `mvp_demo.py` 不再 import `RiskGate` / `RuleEngine` / `match_similar_tail_cases` / `evidence_direction_context` / `split_eligible` 等（F3 源码级断言守护）。RiskGate / RuleEngine 只存在于 `code/decision_service.py` 决策链中（单一实现）。

**Q5：市场规则版本是否按 trade_date 自动判定（date-aware）？**
**YES。** `code/market_rules.market_rule_version_for(trade_date)`：`trade_date >= 2026-05-01 → POST_DAME_EDAM_2026`，否则 PRE。边界验证：`2026-04-30 → PRE`，`2026-05-01 → POST`，`None/非法 → CURRENT`（F6）。DecisionService 的 `context.market_rule_version` 与 `audit.meta` 均按 `target_date` 调用（F7）。

**Q6：2026-05-01 之后的案例是否标 POST？**
**YES。** `Case.from_dict` 在原始数据缺 `market_rule_version` 字段时按 `decision_date` 推断（`market_rule_version_for`）。实跑：`agent/case_library/cases{,_auto}.json` 共 337 条（日期 2026-06-04 ~ 2026-08-04）全部推断为 `POST_DAME_EDAM_2026`，无需迁移数据、不改 PnL/决策字段；显式标注保留（F8）。

**Q7：证据可用性判据是否只有 available_at <= decision_cutoff？**
**YES。** `Evidence.time_eligible` 判据：`available_at <= decision_cutoff`（Time Gate 唯一判据），`available_at` 缺失才回退 `published_at`（兼容旧证据），绝不使用 `initialization_time`（F9 双向验证：published≤cutoff 但 available>cutoff 必须 rejected；published>cutoff 但 available≤cutoff 必须 eligible）。Web 审计复验同步改为 `available_at or published_at`（F10）；旧注释措辞（`published_at <= decision_cutoff 才能…`）已清理。

**Q8：本轮是否修改了任何交易 Alpha / 阈值 / PnL？**
**NO。** 交易核心冻结。Predictive Model、BUY/SELL 阈值、Risk Gate 规则、Rule Engine 业务规则、PnL 定义、Case 业务逻辑、Evidence 方向解读、Settlement 全部未动。F11 回归：5 个 Golden Case 的 final / risk_gate 与 V0.3.1.1 完全一致（B=SELL/PASS、C1=NO_TRADE/REJECT、C2=NO_TRADE/WARNING、D=SELL/WARNING、E=NO_TRADE/REJECT）。本轮全部改动为工程/审计/展示/措辞/版本标签加固。

## 4. 诚实边界

- clean clone 模拟在本机完成（强制 LF + canonical 哈希校验 + DEMO 5 Golden Case）。真正"另一台机器 git clone"的端到端复核建议跑 `python code/tests/_clean_clone_simulation.py`（需要完整数据机；clean clone 上该脚本按设计针对可用路径运行）。
- FULL vs DEMO 一致性（H4/D4）在本完整数据机实跑 5/5；真正 clean clone 上自动 SKIP（需完整数据机复核）。
- `run_tests.py` 在 clean clone（无完整数据）上部分用例会自动 SKIP（H4/D4/FULL-only），SKIPPED 会 > 0——这是设计，不是失败。
- GBK 管道打印 emoji 可能 UnicodeEncodeError（用 `python -X utf8 run_tests.py` 正常）。
